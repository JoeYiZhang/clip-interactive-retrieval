## 5 发现的问题与阻塞

按影响排序，每条都给出证据位置和建议，供交接人决策。“建议动作”中凡涉及改代码的，本次均未执行。

### 5.1 系统代理会拦截所有下载（P0）

- 现象：`HKCU\...\Internet Settings` 的 `ProxyEnable = 1`、`ProxyServer = 127.0.0.1:7897`；`urllib.request.getproxies()` 返回该代理；经代理的请求被重置（`ProxyError ... ConnectionResetError 10054`），`curl.exe` 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`。
- 影响：`pip`、`torch.hub`、`open_clip` 的默认下载全部失败，且报错信息（TLS/凭证）会误导排查方向。
- 证据：本节命令输出；`pip` 重试日志。
- 建议动作：下载命令统一带 `$env:HTTP_PROXY=''; $env:HTTPS_PROXY=''; $env:NO_PROXY='*'`，或关闭系统代理。交接文档需写入这一条。

### 5.2 pip 默认缓存目录会导致挂起（P0）

- 现象：venv 内 `pip 24.0` 使用默认缓存 `%LOCALAPPDATA%\pip\cache` 时，`pip install --upgrade pip`、`pip download six` 等简单命令超过 10 分钟不结束，并伴随持续高 CPU 的子进程。
- 规避：加 `--no-cache-dir`（或 `PIP_NO_CACHE_DIR=1`）后同一条命令数秒完成。
- 影响：直接照抄 README 的安装命令可能“卡住”，容易被误判为网络问题。
- 建议动作：README 安装命令补 `--no-cache-dir`，或在文档中说明该机器现象。

### 5.3 构建隔离（build isolation）在 venv 内挂起（P0）

- 现象：`pip install -e ".[ml,dev]"` 停在 `Installing build dependencies: started`，其派生的嵌套 pip 子进程长时间无进展（与 5.2 同一类现象）。
- 规避：先 `pip install setuptools wheel`，再 `pip install --no-build-isolation -e ".[ml,dev]"`，安装一次成功。
- 影响：`README.md` 现行命令 `python -m pip install -e ".[ml,dev]"` 在本机无法原样复现。
- 建议动作：README 增加 `--no-build-isolation` 备选路径并说明前置 `setuptools`/`wheel`（属文档修改，本次未改）。

### 5.4 会话内 venv 进程只能写工作区（P0）

- 现象：`.venv\Scripts\python.exe` 执行 `os.makedirs` 到 `C:\Users\25062\.cache\...`、`%TEMP%`、`Documents` 均报 `PermissionError: [WinError 5]`；同一台机器上系统 Python（`py -3.12`、Anaconda 3.13）与 PowerShell 对相同路径写入成功，`whoami` 显示两者都是 `LAPTOP-AERSOP15\25062`。
- 影响：`open_clip` 无法自行创建 `~/.cache/clip`，`huggingface_hub` 无法创建 `~/.cache/huggingface`，即使网络可用也会失败（首次报错的直接原因）。
- 规避：借助系统 Python/PowerShell 预置缓存目录与权重文件，venv 侧只读不写。
- 建议动作：交接时确认这是本机/本会话的沙箱策略还是全局策略；若是全局策略，应在 README 增加“预置缓存”步骤，或改用系统 Python 建环境。

### 5.5 HuggingFace 域名不可达，而 open_clip 3.3.0 优先走 HF（P0）

- 现象：`huggingface.co` 连接被拒绝（WinError 10061），`hf-mirror.com` 间歇可用、`resolve` 路径仍失败；`open_clip` 3.3.0 的 `openai` 标签配置为 `{"hf_hub": "timm/vit_base_patch32_clip_224.openai/", "url": ".../ViT-B-32.pt", "quick_gelu": true}`，而 `download_pretrained()` 在 `prefer_hf_hub=True`（默认）时会**清空 url** 只走 HF。
- 影响：`OpenCLIPEncoder` 的默认 `pretrained="openai"` 在本机必然失败；只有临时卸载 `huggingface_hub`（使 `has_hf_hub()` 为 False）才会回落到可访问的 azureedge 直链。
- 证据：`open_clip/pretrained.py` 第 894-926 行；运行时异常栈。
- 建议动作：项目侧应显式支持“本地权重路径”或 `prefer_hf_hub=False`，并把权重获取方式写入实验登记；当前 `encoders.py` 未暴露该参数。

### 5.6 torch 2.9 的 `weights_only` 与 OpenAI TorchScript 权重冲突（P0）

- 现象：`torch.load(path, weights_only=True)` 对 TorchScript 归档直接抛 `RuntimeError: Cannot use weights_only=True with TorchScript archives`；`open_clip` 的 `load_state_dict()` 只捕获 `TypeError`，于是异常穿透，`create_model_and_transforms` 失败。
- 影响：即使权重已下载成功，`ViT-B-32 + openai` 在 `torch 2.9.1` 下仍无法加载；这是本次真实编码必须改用“预先转 state_dict”的根因。
- 证据：`open_clip/factory.py` 第 153-178 行；运行时异常栈。
- 建议动作（三选一，需评审）：① 把 torch 锁到 `<2.6`；② 升级到已处理该异常的 open_clip 版本；③ 在 `encoders.py` 增加本地权重加载分支（属实现修改，本次未做）。

### 5.7 QuickGELU 未实际生效，模型激活为 GELU（P1）

- 现象：`open_clip` 3.3.0 只在 `quick_gelu` 不一致时 `warnings.warn`，不会把标签值写入 `model_cfg`；实测 `visual.transformer.resblocks[0].mlp[1]` 与 `transformer.resblocks[0].mlp[1]` 均为 `GELU`，并伴随告警：`QuickGELU mismatch between final model config (quick_gelu=False) and pretrained tag 'openai' (quick_gelu=True)`。
- 影响：OpenAI ViT-B-32 是用 QuickGELU 训练的，激活不一致会让向量与官方语义偏离；`real_clip_smoke.json` 中“a red circle”Top-1 命中 red_square 可能就是该偏差的表现之一（未做对照实验，不能断言）。
- 建议动作：复现前用 `create_model_and_transforms(..., force_quick_gelu=True)` 或降级到行为正确的 open_clip 版本，并在登记表写明；本次冒烟结果只能作为“链路可用”证据。

### 5.8 批大小引起的编码差异超出常见容差（P1）

- 现象：首张图在“单张批”与“15 张批”两次编码的最大绝对差为 `6.83e-04`。
- 影响：`docs/02` 的 FR-01 要求“固定输入重复编码在容差内一致”，但未定义容差与批大小；若后续用不同批大小生成图库嵌入与查询嵌入，会引入不可追溯的漂移。
- 建议动作：明确“编码容差 ≤1e-5”且“图库与查询使用同一批大小与设备”，并写入 `docs/02` 或 `docs/04`。

### 5.9 文档中的 Python 版本与实际不一致（P2）

- 建议动作：以本报告第 2 节为准更新环境记录；若确有 3.12.14 环境，需补充其路径。
