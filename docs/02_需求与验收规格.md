# 需求与验收规格

## 1 项目范围

系统包含两条评测轨道：

- 单轮组合图像检索：参考图像加修改文本，输出排序图片列表。
- 多轮交互检索：在初始查询基础上接收显式正负反馈和补充文本，逐轮更新查询。

第一版不训练 CLIP 编码器，不把生成式图片模型作为主流程，不承诺面向生产环境的高可用性。

## 2 功能需求

| 编号 | 级别 | 需求 | 验收方法 |
|---|---|---|---|
| FR-01 | Must | 对参考图像和修改文本生成归一化向量 | 固定设备、模型、预处理和批大小后，重复运行最大绝对差不超过 `1e-5`；范数接近 1；批大小必须登记。跨批大小差异单独记录 |
| FR-02 | Must | 支持 image-only、text-only、等权和可配置加权融合 | 单元测试覆盖四种模式；配置进入实验登记表 |
| FR-03 | Must | 使用精确内积索引返回 Top-K | 与手工余弦排序一致 |
| FR-04 | Must | 拒绝编码器与索引版本不匹配的请求 | 契约测试触发明确错误 |
| FR-05 | Must | 保存逐查询排名和总体指标 | 结果文件可重算 R@K |
| FR-06 | Must | 记录随机种子、数据、代码、模型和索引版本 | 实验登记表必填检查 |
| FR-07 | Should | 支持带初始锚点的多轮查询更新 | 正反馈、负反馈、冲突反馈和漂移超限测试 |
| FR-08 | Should | 支持 HNSW 或 IVF 近似检索对比 | 同时报告相对精确检索的 ANN Recall@K、延迟和内存 |
| FR-09 | Later | 支持 MLP 二阶段重排序 | 同骨干基线消融和离线发布门禁通过 |
| FR-10 | Later | 支持 LLM 结构化反馈 | Schema、超时、低置信度和回退测试通过 |

## 3 非功能需求

| 编号 | 需求 | 当前建议门槛 |
|---|---|---|
| NFR-01 | 可复现性 | 同配置重复运行主要指标差异不超过 0.1 个百分点；训练实验报告三随机种子 |
| NFR-02 | 可追溯性 | 每个结果能追溯到配置、数据、编码器、索引、代码和随机种子 |
| NFR-03 | 正确性 | 所有向量有限且已归一化；索引和查询维度匹配 |
| NFR-04 | 近似召回 | ANN Recall@50 相对 IndexFlatIP 建议不低于 0.98 |
| NFR-05 | 在线延迟 | 硬件基准后冻结；暂定无 LLM P95 不高于 2 秒，带 LLM 不高于 5 秒 |
| NFR-06 | 隐私 | 反馈数据去标识化；不记录身份证、手机号等非必要信息 |
| NFR-07 | 可恢复性 | 模型或索引发布失败时可切回上一登记版本 |

## 4 第二阶段完成定义

第二阶段验收必须同时满足：

- CIRR 和 FashionIQ 的数据来源、许可、版本、划分和校验值已登记。
- CLIP 模型、预处理、向量维度和权重哈希已登记。
- Image-only、text-only、等权和验证集加权四个基线已运行。
- CIRR 官方验证集报告 R@1/5/10/50 与 subset R@1/2/3；FashionIQ 按类别及类别平均报告 R@10/50。
- 保存逐查询排序结果、总体指标和失败案例。
- 在干净环境按 README 能重建至少一个数据集的嵌入与精确索引。
- 测试全部通过，且不存在未解释的版本不匹配或数据泄漏。
