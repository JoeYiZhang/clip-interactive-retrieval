# 实验计划与登记规范

## 1 基线矩阵

| 编号 | 输入与融合 | 多轮反馈 | LLM | 重排序 | 目的 |
|---|---|---|---|---|---|
| B0 | image-only | 无 | 无 | 无 | 检查图像贡献 |
| B1 | text-only | 无 | 无 | 无 | 检查文本捷径 |
| B2 | 0.5 图像加 0.5 文本 | 无 | 无 | 无 | 最小组合基线 |
| B3 | 验证集选择权重 | 无 | 无 | 无 | 第二阶段主基线 |
| A1 | B3 | 普通 Rocchio 式更新 | 无 | 无 | 反馈收益 |
| A2 | B3 | 带初始锚点与漂移保护 | 无 | 无 | 查询漂移控制 |
| A3 | B3 | A2 | 结构化解析 | 无 | LLM 增益和成本 |
| A4 | B3 | A2 | 结构化解析 | MLP | 完整系统 |

第二阶段只要求 B0-B3。没有 B0-B3 的稳定结果，不开始 A1-A4。

## 2 主要指标

- CIRR：Recall@1/5/10/50 与 Recall-subset@K。
- FashionIQ：按 Dress、Shirt、Toptee 报告 Recall@10/50，并报告平均值。
- CIRCO：若接入，使用 mAP@K，不把它与单目标 Recall 混为一个数字。
- 近似索引：ANN Recall@K 相对 IndexFlatIP、P50/P95 延迟、内存、构建时间。
- 多轮阶段：Success@K@turn、平均成功轮数、每轮增益和漂移回退率。

## 3 实验登记规则

每次实验开始前在 `experiments/registry.csv` 新增一行，结束后补齐结果路径和状态。禁止先挑选最好结果再补登记。

必填字段：

- 实验 ID、日期、负责人和任务轨道；
- 数据集、划分和数据清单版本；
- 编码器、预处理、融合、索引和重排序版本；
- 随机种子、代码版本和完整配置；
- 主要指标、结果文件路径、状态和异常说明。

## 4 结果文件结构

```text
artifacts/metrics/<experiment_id>/
  config.toml
  environment.json
  summary.json
  rankings.jsonl
  failures.jsonl
  stdout.log
```

`rankings.jsonl` 每行至少包含 query_id、target ids、ranked ids、scores 和模型版本。论文表格必须由这些结果文件自动汇总，不手工抄写数字。

## 5 数据泄漏检查

- 使用官方公开划分，不自行把验证集目标加入训练。
- 反馈数据按用户或会话分组切分。
- 合成三元组记录其源图片，源图片跨集合时视为泄漏。
- 权重和融合系数只在验证集选择，测试集只运行一次最终配置。
- 每个报告明确区分验证集结果和官方测试集结果。

## 6 可重复运行

无训练基线固定一个随机种子并重复两次验证逐查询排名一致。带训练实验使用至少三个随机种子，报告均值和标准差。任何不确定性来源都必须记录，而不是用一次最好结果代替。
