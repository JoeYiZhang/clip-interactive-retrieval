## 2. 本次修复的计算精度问题

实测发现，默认 cuDNN 允许 TF32 时，对单张参考图编码与旧批量缓存的向量有偏差。第一条查询的图片向量最大差异约 0.00056227，融合后约 0.00021310；仅文字编码的差异约 8.57×10⁻⁸。固定 CUDA 矩阵乘法和 cuDNN 都不使用 TF32 后，该查询差异降至约 8.94×10⁻⁸，全部 8 条查询最大差异为 1.64×10⁻⁷。

因此本轮采用以下处理：

- 推理命令显式关闭两处 TF32；直接调用底层类时，未关闭则明确报错。
- 新建 LaSCo/CIRCO 缓存的构建脚本也固定这两个设置，并在计划中记录 `encoder_precision`，该字段参与缓存身份哈希。
- 新缓存目录为 `artifacts/cache/lasco-train-engineering-fp32-v2`，旧 v1 缓存保持原样，分别保存一致性证据。
- 旧缓存未记录精度时会在输出中注明 legacy，不应未经对拍直接推广；本次仅确认固定 8 条工程样本的兼容性。

**文档 22 中旧 v1 缓存的原样续跑命令属于历史协议。** 新构建脚本增加了精度契约，不能追加到旧目录；重建请使用本文件的 v2 路径。后续完整缓存尚未创建，可继续使用文档 22 的 `*-full-v1` 新目录，默认按固定精度编码。训练权重未重训，既有训练恢复点和旧实验原始证据均保留。

## 3. 调用流程

```mermaid
flowchart LR
    A[已入库参考图片 ID 与自由英文描述] --> B[验证权重 缓存 编码器与精度]
    B --> C[检查参考原图内容哈希]
    C --> D[冻结 CLIP 重新编码图片与文字]
    D --> E[已保存的 LaSCo 融合头]
    E --> F[精确内积检索并排除参考图]
    F --> G[检查结果图片内容 输出 Top-K 与版本记录]
```

模型调用只使用参考图片和用户描述；缓存中的训练文字、正例标签不会传入融合头。检索分数是归一化向量的相似度，不是概率。Top-K 大于可用候选数时，返回全部可用非参考图并记录实际数量。

缓存读取会暂时加载图片与文字矩阵；当前接口复用既有完整缓存校验器，之后只保留图片索引和图片元信息。全量加载的内存与延迟需在正式数据到位后测量。
